### 0.3 ⚠️ 本轮独立评审发现：论文场景描述与预注册注册表不符（4 处）

我逐个场景比对了论文 §5/§6.2 描述、`experiments/racer-v2-v05-scenario-registry.json`（预注册冻结）与 envelope 实测 `domain` 字段。**envelope 与注册表 100% 一致，论文描述有 4 处错误**：

| 场景 | 论文原描述 | 注册表 + envelope 实测 | 性质 |
|---|---|---|---|
| S1 | flight / 抹除最优 / force_error | flight / omission / force_error | ✓ |
| S2 | flight / **抹除最优** / rate_limit | flight / **price corruption (抬至预算边界)** / rate_limit | ✗ 机制错 |
| S3 | hotel / 抹除最优 / wrong_tool | hotel / omission / wrong_tool | ✓ |
| S4 | shop / **抹除最优** / force_error | shop / **stock falsification** / force_error | ✗ 机制错 |
| S5 | hotel / **价格腐蚀(边界)** / rate_limit | hotel / **stale quote (陈旧报价)** / rate_limit | ✗ 机制错 |
| S6 | shop / 抹除最优 / rate_limit | shop / omission / rate_limit | ✓ |
| S7 | **shop / 库存伪造** / wrong_tool | **flight / stale quote** / wrong_tool | ✗ **域与机制双错** |

连带错误：摘要与 C3 将误导证据模式记为"**三类**"（目录抹除/价格腐蚀/库存伪造），实际注册表定义为**四类**（omission 3 例、price-boundary corruption 1、stock falsification 1、stale quote 2）；域分布论文隐含为 flight 2 / hotel 2 / shop 3，实测为 **flight 3 / hotel 2 / shop 2**。

**严重性定位**：这是**文档层描述错误，不影响任何数字、统计、审计或结论**——所有行为数据、准入门控、统计均基于 envelope 的 `domain`/`scenario_id` 结构化字段（那些字段正确且与注册表一致）。但它说明**"文档—注册表一致性"缺少一道自动化核对**：预注册注册表是权威源，论文描述却凭人工转写、未被校验。前两轮我抽查"数字 vs 产物"全部一致，本轮抽查"文本 vs 注册表"就抓出了问题——这本身就是对该稿件核对流程的一个反向发现。

**处置**：作者已在收到本报告后按注册表口径修正论文 §5、§6.2 表、摘要、C3（四类机制、正确域分布）。修正后论文描述与注册表/envelope 三方一致。

**结论：论文的实证声明（数字层）与产物高度一致，未发现数字造假或夸大。唯一缺陷是场景描述文本层与预注册注册表不符，已修正。**

## 1. 各维度评分（1–10）

### 1.1 新颖性（Novelty）：6.5（前轮 6.5，持平）
核心主张（"恢复=须经审计的断言、预测有害则弃权"）与 v0.4 相比**未变**——v0.5 是覆盖扩充而非方法创新。与 CausalFlow 的区分仍是实质的（可复算回执、审计准入、否决语义），但技术新颖性维持"中高非突破"。重放机制直白、门控为阈值、G1–G8 多为工程记账。**规模扩大不提升新颖性。**

### 1.2 技术深度（Technical Depth）：5.5（前轮 5.5，持平）
机制仍偏浅。v0.5 新增的工作量在**环境工程**（单引擎三域分派、7 场景陷阱构造、域分派下的 oracle 参数化）而非**算法深度**。域分派是 `DOMAIN_SPECS` 字典查表，场景是配置枚举，oracle 是既有谓词的同构复制——这些都是"把同一机制铺到更多地方"，不是"更深的机制"。审计基础设施（配对身份、去重证明、G4 三形、v0.4/v0.5 oracle 链）仍是全文最深的部分，但属"可信系统工程"。

### 1.3 实验设计与方法论严谨性（Experimental Design & Rigor）：7.0（前轮 6.0，**+1.0**）
**实质改善，是本轮最大涨幅来源。**
- 覆盖广度从"单域 65 episode"扩到"三域 800 episode、双模型、11,200 记录"，并**按第二轮评审的处方**（补第二模型 + 扩域 + E3 ≥5 场景 ×≥10 种子）逐项落地——这是"照批评打靶"的教科书式响应；
- E3 从 2 场景扩到 7 场景 ×10 种子 ×2 模型，且场景化独立性经注册表预注册 + 计算化校验（`validate_v05_scenarios.py` 成对轴检查 + 回归测试）——独立性主张有机械化依据而非口述；
- 预注册纪律保持（v0.5 冻结 2026-09-09T04:20:01Z，早于首个 v0.5 产物）；R.2 GO 六条件含"分离方向 12/14 ≥ 11/14"的量化门控与偏离配额；
- 模型级偏差（DeepSeek 失败分母 69 vs GLM 111、故障触发 cell 8/33 vs 17/33、no_cf 直接应用 0 vs 106）**全部如实披露**并解释机制。

**仍扣分**：
- 7 场景的"独立性"是**组合枚举意义上的**（域 × 误导证据 × 触发故障），不是**危害类型意义上的**——见弱点 A′；
- 主表 harm 恒为 0（无陷阱设计），使主表**不测危害维度**，RACER vs 重试族在主表结构性零差；差异化证据仍 100% 集中在 E3 轨道；
- 5→10 种子改善了精度，但仍是复现性种子而非 i.i.d. 样本（作者披露）。

### 1.4 结果可信度（证据链）：7.5（前轮 7.5，持平）
数字层依旧最强：11,200 记录、四份审计全 PASS 零排除、我抽查的每一个关键统计（H-E3a/H-E3b/重试族联合/主表域分层/逐域 Holm）都与产物严丝合缝。v0.5 还新增了**跨模型交叉验证**这一独立证据维度（judge 弃权模式在 DeepSeek 上逐场景复现，强化了"基线属性"而非"模型噪声"的定性）。扣分因：(i) E3 分离仍是构造性的（陷阱被设计为"重试即有害"，见弱点 A′）；(ii) 本轮发现的场景描述错误说明文档核对存在缺口（虽已在 0.3 定位为文档层）。

### 1.5 写作与呈现：7.5（前轮 8.0，**−0.5**）
结构、术语一致性、局限章节的坦诚度仍属上乘；§6.2a/6.2b 的新增小节与 v0.1 step-position 缺陷披露（K.4）都写得清楚。**扣分唯一原因是 0.3 的场景描述错误**——4 处场景机制/域写错、摘要机制计数错误（三类 vs 四类）。对一篇以"可复现、可审计"为卖点的稿件，正文描述与预注册源不符是与其自身标准相悖的瑕疵；虽不影响结论，但应由自动化核对杜绝。

### 1.6 影响力潜力（Impact Potential）：6.5（前轮 5.5，**+1.0**）
双模型 + 三域 + 七场景显著抬升了外部效度声明，"在真实 LLM 执行中可行"的主张现在有跨模型交叉支撑，不再是单模型孤证。但天花板仍受两点压制：(i) 三域由**同一引擎**分派（工具名与属性键不同、结构同构），"跨域"的说服力低于"跨独立环境"；(ii) 危害语义单一（全部是"提交次优确认"），限制了对"不可逆副作用"的泛化主张。部署前提（需可审计环境）仍由作者自陈、边界较紧。

## 3. 最致命 3 个弱点（按严重性排序，均较前轮改写）

### 弱点 A′：危害语义单一 + 域同构 —— "覆盖扩充"未转化为"危害多样性"（严重性：致命，最高）
- **表现**：7 个 E3 场景共享**同一个危害谓词**（`confirmed ∧ ¬optimal_selection`，即"提交次优不可逆决策"）。注册表 `purpose` 字段自陈："Scenarios vary HOW the agent is misled or fails, **not what harm means**"。因此 v0.5 实际证明的是"RACER 在**一种**不可逆危害（次优确认）上的必要性被 7 种诱导方式重复验证"，而非"在多种不可逆危害上普适"。同样地，三域由单引擎 `DOMAIN_SPECS` 分派，工具名/属性键不同但**交互结构同构**——"扩域"的实质收益低于名义。危害类型维度上，v0.5 相较 v0.3 的 2 场景**并未增加新种类**（仍是次优确认）。
- **为何致命**：这决定稿件天花板。审稿人会问："你的验证层在'重复扣款''余额不结算''跨实体误操作''部分撤销不可逆链'这类**不同**不可逆危害上也必要吗？"——当前证据无法回答，而这类危害恰恰是"不可逆"在真实系统中最痛的部分。
- **是否可修复 / 代价**：可修复，代价中高。需在引擎中加入至少 2–3 类**不同终局语义**的危害（如：幂等性缺失导致的重复副作用、跨实体写、不可回滚的多步链），并让危害谓词随之分型。

### 弱点 B′：主表不测危害维度，差异化证据仍全部集中在 E3（严重性：高）
- **表现**：v0.5 主表 9,240 记录 harm **恒为 0**（无陷阱设计），RACER 与 fixed_retry 在三域两模型上**结构性零差（p=1.0）**。这意味着"扩主表到三域双模型"扩大的是**恢复率**这一无差异化维度；能分离 RACER 与朴素策略的证据，**仍然 100% 来自 E3 轨道**。前轮弱点 A 的结构（"全部差异化压在极薄 E3 上"）在**结构性意义上并未改变**，只是 E3 内部从 2×5 增厚到 7×10×2。
- **为何重要**：主表看起来体量巨大（9,240 行）却对核心命题零贡献，容易被审稿人识别为"规模注水"。真正有价值的是把无害的不可逆陷阱引入主表（使主表也具备 harm 维度），而非仅增加恢复率样本。
- **是否可修复 / 代价**：可修复，代价中等。在主表部分 cell 注入不可逆陷阱（类似 E3 机制但混入常规任务流），使主表同时产出 harm 维度。

### 弱点 C′：文档—预注册一致性缺少自动化核对（严重性：中，本轮新发现）
- **表现**：论文 §5/§6.2 的 4 处场景描述与预注册注册表不符（含 1 处域错、3 处机制错），摘要机制计数错误。虽为文档层、不影响任何数字，但对一个以"可审计、可复现"立身的稿件，正文与冻结源不一致是与其自身标准相悖的瑕疵。
- **根因**：场景描述由人工从注册表转写进论文，无"注册表→论文"的一致性命中检查；相比之下"数字→产物"的核对在 v0.5 中做得很好（本轮抽查全部一致）。
- **是否可修复 / 代价**：已修复（本轮），代价极低。**建议固化为脚本**：从注册表生成场景表片段，阻断人工转写漂移。

> 说明：前轮弱点 B（单模型）**已彻底关闭**（DeepSeek 全矩阵进主表且为复现分析）；前轮弱点 A/C 获**部分回应**（场景数与域数达标，但危害语义维度未扩，且主表未引入 harm 维度）；本轮 A′/B′ 是前轮 A 的**更精确重述**——v0.5 满足了"数量指标"却未满足"多样性指标"。

## 6. 到 7.5–8.0 的具体路径（重新估算）

前轮路径（"补模型 + 扩域 + 扩场景"）已被证明**不足以**达到 7.5–8.0。修正后的路径必须触及**多样性**而非数量：

1. **危害语义分型（+0.5～0.8，最高优先）**：在引擎中实现 ≥3 类**终局语义不同**的不可逆危害——(i) 幂等性缺失型（重复副作用，如重复扣款）；(ii) 跨实体写型（改错实体且不可撤销）；(iii) 多步不可逆链型（若干步后进入不可回滚状态）。让 harm 谓词分型、E3 场景覆盖至少 2 类新危害。这一步直接关闭弱点 A′。
2. **主表引入 harm 维度（+0.3～0.5）**：把不可逆陷阱混入常规主表 cell，使主表同时产出 harm 维度并出现 RACER vs 朴素策略的实质分离（关闭弱点 B′ 的"规模注水"观感）。
3. **非同构第二环境（+0.3～0.5）**：至少 1 个不共享引擎结构的独立环境（不同交互步长 3–10 步、多实体、部分可观测），替代"同引擎域分派"的扩域叙事。
4. **种子升级（+0.1～0.2）**：关键结论的种子从 10 提到 ≥20 并做种子级方差分解。

**预估**：完成 1+2 后约 **7.3–7.5**；再完成 3 后约 **7.6–8.0**，顶会主会把握升至 **20–30%**。

## 7. 结论（直白版）

v0.5 是一次**执行力极强的处方响应**：第二轮指出的三项覆盖短板（第二模型、扩域、E3 场景族）全部落地，11,200 记录零排除、双模型交叉复现、四重回归零漂移，证据链依旧标杆级。分数从 6.3 升到 **6.8**，投稿定位从"仅够 Findings/workshop"上移到"**稳进 *ACL Findings / JAIR / TIST，主会可试但不建议直投**"。

但**没有达到第二轮预期的 7.5–8.0**，且原因清晰可诊断：v0.5 补齐的是**数量指标**（3 域、7 场景、2 模型），而非**多样性指标**——7 个 E3 场景共享同一个危害谓词（"提交次优确认"），三域由同一引擎同构分派，主表harm 恒为 0 对核心命题零贡献。因此审稿人仍可一句话命中："你用一个危害 × 七种诱导，和三域同构分派，证明了可审计恢复的必要性。"这句话目前无法反驳。

**下一步的最优投资是"危害语义分型"与"主表引入 harm 维度"**，而非继续堆场景数或种子数——前者是决定天花板的短板。另需固化"注册表→论文"的一致性命中检查，避免本轮检出的文档漂移复发。
